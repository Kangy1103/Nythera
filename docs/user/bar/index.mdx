Bars are defined as named subtables under `[bar.*]`. Each bar is spawned on every connected monitor, then per-monitor overrides are applied.

Widget hover tooltips open on the side of the bar facing into the screen (below a top bar, above a bottom bar, and beside a left or right bar), so they do not cover other bar widgets.

```toml
[bar]
order = ["main"]              # layer-shell creation order

[bar.default]
position           = "top"       # top | bottom | left | right
enabled            = true
auto_hide          = false       # slide out after pointer leaves; reveal from edge trigger strip
auto_hide_delay_ms = 0           # wait after pointer leaves before hiding, 0 to 600000 ms
smart_auto_hide    = false       # show when the active workspace is empty; hide when it has windows
show_on_workspace_switch = true  # with auto_hide: briefly reveal when the active workspace changes
reserve_space      = true        # reserve compositor exclusive zone / push windows away
layer              = "top"       # top | overlay; overlay appears above fullscreen apps

thickness          = 34          # bar cross-axis size in pixels (height for horizontal, width for vertical)
background_opacity = 1.0         # 0.0 (transparent) to 1.0 (opaque)
compositor_blur    = true        # publish a compositor blur region for this bar
border             = "outline_variant"   # color role or #RRGGBB for the bar outline
border_width       = 0.0         # inside outline width in pixels; 0 disables it
shadow             = true        # cast the global [shell.shadow]
contact_shadow     = false       # dark gradient between an attached panel and the bar (depth at the seam)
panel_overlap      = 1           # logical px an attached panel overlaps the bar edge to hide the seam
radius             = 12          # global corner radius fallback
radius_top_left    = 12
radius_top_right   = 12
radius_bottom_left = 12
radius_bottom_right = 12
concave_edge_corners = true      # carve the screen-edge corners inward; requires margin_edge = 0
margin_ends        = 100         # inset from each end of the bar along its main axis
margin_edge        = 0           # distance from the nearest screen edge (positive values float the bar)
margin_opposite_edge = 0         # extra reserved space on the inward side of the bar (below for top, above for bottom)
padding            = 14          # main-axis padding from bar edges to start/end widget sections
widget_spacing     = 6           # gap between widgets within a section
hover_highlight    = true        # softly tint the widget under the mouse pointer with its foreground color
show_tooltip       = true        # show hover tooltips for widgets on this bar; per-widget show_tooltip overrides
scale              = 1.0         # content scale multiplier for icons, spacing, and base text size
font_scale         = 1.0         # additional text-only scale multiplier
font_weight        = 500         # CSS weight 100–1000 (e.g. 400 regular, 700 bold); primary label weight for bar widgets
font_family        = ""          # typeface for this bar's widgets; empty inherits the global font

# Default capsule style for all widgets on this bar (see Widget Capsule section)
capsule            = false
capsule_fill       = "surface_container"
capsule_thickness  = 0.76          # capsule size across the bar as a fraction of bar thickness (1.0 fills the bar)
capsule_radius     = 8.0            # omit for automatic pill radius
capsule_opacity    = 1.0
# capsule_border   = "outline_variant"   # omit this key for no border by default
capsule_border_width = 1.0          # outline thickness in logical pixels (0-8), drawn only with capsule_border

start  = ["launcher", "wallpaper", "workspaces"]
center = ["clock"]
end    = ["media", "tray", "notifications", "clipboard", "network", "bluetooth", "volume", "brightness", "battery", "control-center", "session"]
```

Radius precedence: `radius` is the global fallback; per-corner values override it when provided.

#### Concave edge corners

Keep every radius non-negative. `concave_edge_corners = true` selects which pair of corners uses the concave shape; `false` leaves all four corners convex. Concavity requires `margin_edge = 0`, because a floating bar does not touch the screen edge.

For a full-length bar (`margin_ends = 0`), the two **inner-edge** corners facing away from the docked screen edge become concave:

| Bar position | Concave corners                             |
| ------------ | ------------------------------------------- |
| `top`        | `radius_bottom_left`, `radius_bottom_right` |
| `bottom`     | `radius_top_left`, `radius_top_right`       |
| `left`       | `radius_top_right`, `radius_bottom_right`   |
| `right`      | `radius_top_left`, `radius_bottom_left`     |

For an inset bar (`margin_ends > 0`), the two corners touching the screen edge become concave instead, and the bar flares into the end margins. The carve is limited by the configured corner radius, half the bar `thickness`, and the available `margin_ends`.

Multiple `[bar.*]` entries are supported - each is independently configured and rendered on all monitors.

`[bar].order` controls the order Noctalia creates bar layer-shell surfaces. This matters only for bars with `reserve_space = true`, and the compositor still owns the final exclusive-zone arrangement. Names omitted from `order` are appended after the listed names.

### Dead zone actions

The **dead zone** is the bar margin outside the start/center/end widget sections - typically the inset created by `margin_ends`. It takes the same bindings bar widgets do, under `[bar.<name>.dead_zone.actions]`:

```toml
[bar.default.dead_zone.actions]
left = "panel-toggle launcher"
middle = "exec kitty"
scroll_up = "volume-up"
scroll_down = "volume-down"
back = "media previous"
forward = "media next"
```

All nine gestures are available, and an action is an IPC command, `exec <command line>`, or `none` - see [Widget Actions](/noctalia/bar/actions/) for the full vocabulary. Panel actions anchor at the pointer, since there is no widget to anchor to.

Right-click opens Control Center unless you bind `right` to something else. While an attached panel is open, right-click anywhere on the bar still toggles Control Center unless the click lands in the dead zone and `right` is bound.

Per-monitor overrides can carry their own `[bar.<name>.monitor.<match>.dead_zone.actions]` table, which replaces the bar's rather than merging with it.

### Dead zone click-through

Set `click_through = true` to drop the dead zone from the bar's input region, so clicks there reach the window underneath instead of the bar. This suits a transparent bar that only shows a few widgets, such as a floating workspace strip. Only interactive widgets (stretched across the bar's thickness) take input; spacers and widgets with `interactive = false` pass clicks through as well, and dead zone actions no longer fire. Auto-hide bars ignore `click_through`.

```toml
[bar.default.dead_zone]
click_through = true
```

Per-monitor overrides accept `click_through` too, under `[bar.<name>.monitor.<match>.dead_zone]`.

## Per-monitor overrides

Inside a bar, add named monitor subtables under `[bar.<name>.monitor.*]`. **First match wins**, in file order.

```toml
[bar.default.monitor.dp1]
match              = "DP-1"    # connector name or description substring
position           = "bottom"  # top | bottom | left | right
enabled            = true
thickness          = 44
background_opacity = 0.9
compositor_blur    = false
border_width       = 1.0
radius             = 0
radius_top_left    = 12
radius_top_right   = 12
radius_bottom_left = 0
radius_bottom_right = 0
padding            = 20
widget_spacing     = 6
start              = []
center             = ["workspaces"]
end                = ["volume", "clock"]
```

**`match` resolution** - compared against:

1. Exact connector name (`eDP-1`, `DP-1`, `HDMI-A-1`, …)
2. Any substring of the monitor description string (`"LG"`, `"4K"`, `"DELL"`, …)

`match` defaults to the subtable key name when omitted, so `[bar.default.monitor."DP-1"]` without a `match` field works too.

Only the fields you specify are overridden; everything else falls through to the `[bar.*]` defaults. Supported override fields: all bar fields including `position`, `dead_zone`, plus `auto_hide`, `smart_auto_hide`, `show_on_workspace_switch`, `reserve_space`, `layer`, `scale`, `font_scale`, `background_opacity`, `compositor_blur`, `color`, `font_family`, and all `capsule_*` keys.

`compositor_blur = true` publishes the bar's shape as a blur region when the compositor supports `ext-background-effect-v1`. Set it to `false` to clear the bar's blur request without changing blur for panels, the dock, notifications, or other surfaces. This setting is independent of `background_opacity`, defaults to `true`, applies immediately on reload, and can be overridden per monitor. In the Settings GUI it lives under **Bar → Effects** and only appears when the compositor supports `ext-background-effect-v1`; on other compositors the key has no effect.

`surface_mode` selects the bar background. `"full"` uses the normal continuous bar; `"islands"` draws one rounded, translucent background around each complete start, centre and end section. Empty sections disappear. Capsule groups retain their spacing and hover behaviour, with their individual backgrounds suppressed in islands mode. Rounded island shapes define input and compositor blur regions, so gaps pass through to the desktop. The previous capsule-only islands presentation has been replaced. Choose **Full Bar**, **Floating Islands**, or **Dynamic Island** under **Bar → General → Surface**. All three modes support every bar edge and per-monitor overrides.

`dynamic_center = true` smoothly animates changes in the size of the existing centre section. It uses precisely the widgets selected in the bar editor; it does not insert a clock, media player, visualiser or transport controls. Add and configure those using the shell's existing widgets. Existing accordion groups continue to control hover expansion. The feature defaults to false and follows the global motion settings. Find **Dynamic Centre** under **Bar → Effects**, including per-monitor settings.

**Bar → Effects → Transparency** offers **Custom**, **Solid**, **Soft** and **Glass**, globally and per monitor. The presets share the native panel background opacities: Solid 100%, Soft 80%, Glass 55%. Custom retains the saved numeric Opacity slider; selecting a preset does not overwrite that value. The TOML key is `transparency_mode = "custom" | "solid" | "soft" | "glass"`.

### Mode-aware settings

Choose the presentation under **Bar → General → Surface**. Settings use the existing conditional visibility system, including effective per-monitor overrides. Dynamic Island controls appear only in that mode; widget lanes, capsule styling, dead-zone actions and Dynamic Centre return in Full Bar or Floating Islands. Automatic hiding controls are omitted for Dynamic Island, which does not use automatic hiding. Common thickness, content/font scale, colour, transparency and border controls remain available.

Frame controls appear only with **Screen Wrap** enabled. Corner Join Distance appears only for Floating Islands, and Window Clearance requires **Reserve Space**. Saved edge margins and shadows are hidden while wrap owns those properties. Individual corner overrides are shown only for an unwrapped Full Bar. The numeric opacity control appears only with **Custom** transparency. Timer/alarm detail controls follow their respective event toggles. Hiding a setting never resets its value; switching modes restores the saved configuration. These rules also apply to settings search and automatically remove empty groups.

### Dynamic Island

Select **Bar → General → Surface → Dynamic Island** (`surface_mode = "dynamic"`). It is a standalone event-driven presentation, separate from Full Bar and Floating Islands. The usual start/centre/end widget layouts remain saved and return when switching back. Screen Wrap is independent, on all four edges.

#### Compact feedback and native tools

The island supplies compact event feedback. **Hovering opens the actual registered Noctalia tool directly**, growing out of the island; there is no intermediate preview card or duplicate expanded player/audio/notification UI. Clicking also opens the corresponding native tool. The resting clock opens Dashboard/Home even when a media player is available.

| Compact state | Content | Native destination on hover/click |
| --- | --- | --- |
| Resting | Clock | Dashboard/Home |
| Media | Artwork and track title | Media |
| Volume / microphone | Icon, percentage and level bar | Audio, including existing output/input controls |
| Brightness | Icon, percentage and level bar | Monitor |
| Notification | Icon and summary | Notifications |
| Call | Summary and supported compact phone actions | Notifications |
| Timer / alarm | Countdown/alert and compact acknowledgement controls | Dashboard/Home |

The existing `PanelManager` opens its registered `ControlCenterPanel` with the relevant context. Native tool settings, tab selection, keyboard handling, menus, popups and dismissal remain with that host. Dynamic Island adds a scoped attached presentation: the native reveal's progress drives both its content clip and the island's widening/lengthening join. It does not create a second Control Center instance or recreate native controls.

During expansion, the existing native panel surface extends back through the island neck and owns the complete background and theme-driven perimeter. The shared frame excludes that ownership rectangle from its paint and client blur regions. The native host reads the live output contour and updates only its own contribution, preserving adjoining bars. With Screen Wrap, both use the same frame contour; without it, one rounded native background covers neck and tool. Native content and controls remain in their existing panel host. This prevents live backdrop blur from sampling a separately tinted island and producing a dark band at the join. Closing returns background ownership to the compact island. All four edges are supported; no full-screen panel buffer is introduced.

The island and Screen Wrap use the native `noctalia-bar-*` surface namespace so existing compositor layer-effect rules cover them. These are compatibility identifiers, not project branding. A later Nythera identifier migration must update matching external rules at the same time. On the current Umbriel session, blur is supplied by those rules because the client background-effect protocol is not advertised. Solid/Soft/Glass select the shell's opacity/card treatment; they cannot enable compositor blur on an unmatched layer.

**Panels → Effects → Transparency** remains the existing Solid/Soft/Glass control. It now controls the outer background of tools opened from Dynamic Island as well as their native card translucency. The island blends to that same opacity during expansion. Choose Glass for both Bar and Panels for matching 55% outer backgrounds; internal control/card surfaces retain their native contrast. Ordinary attached panels retain their existing bar-opacity behaviour.

Hover waits 180 ms before opening the native tool, without taking keyboard focus. Compact call/timer/alarm action hit areas do not auto-expand. Clicking the island explicitly holds the native tool open until its normal Close/Escape/outside dismissal. Clicking a hovered native tool enables normal keyboard interaction; focused editable controls, popups and drags hold the tool open. The pointer can cross from the island into the native tool. A 250 ms leave grace allows that handoff; hovering the tool, dragging a control or using one of its popups holds it open. Leaving both surfaces retracts it. Native Close/Escape/outside-click behaviour remains available. **Open Native Tool on Hover** controls hover activation; clicking remains available if it is disabled. The tools use their native sizing settings; the old bespoke **Island Expanded Width** control was removed. `dynamic_width` is accepted only for legacy profile compatibility and no longer sizes native tools.

#### Compact presentation and optional additions

Compact content fades out over 120 ms, changes, then fades in over the same 300 ms base duration as resizing. This follows global Motion settings. Width/height is measured from the title, artwork, action controls and activity indicators, bounded to the output and a scaled 76–420px main-axis range. Text/font and artwork/action sizes follow bar scaling within the bar thickness. Descriptive titles remain available on vertical bars, rotated anticlockwise; percentages, clocks and countdowns stay upright. Shared font family/weight controls live in Bar → Layout and remain visible for Dynamic Island.

Four mode-aware switches in **Bar → Effects**, also per monitor:

- **Activity Indicators** (`dynamic_activity_indicators`, default true): a running countdown stays visible during another event. MIC/CAM/SHARE reflect filtered live PipeWire capture activity, using the existing privacy filters. These are capture indicators, not a claim that an arbitrary recorder is running.
- **Privacy Feedback** (`dynamic_privacy`, default true): existing privacy OSD transitions enter the compact island.
- **Device Feedback** (`dynamic_devices`, default true): existing Wi-Fi, Bluetooth and power-profile OSD feedback enters the island; native destinations are Network, Bluetooth and Power. The island switches control interception; disabling them restores the ordinary OSD path and its normal preferences. Connection notifications use the normal notification path.
- **Compact Visualiser** (`dynamic_visualizer`, default false): the existing audio visualiser/spectrum service draws a small themed strip during compact Playing media feedback. It is released when hidden, paused, preempted, expanded or disabled; no second CAVA process/player is launched. The option is shown only when Island Media is enabled.

Explicit `call.ongoing` metadata is labelled as an ongoing call. It does not infer call connection from microphone activity or invent unsupported actions. Call lifecycle remains source-owned.

#### Registered events

| Event | Trigger |
| --- | --- |
| Volume / microphone | Existing Noctalia audio feedback: default-device level, mute or route changes, including its feedback commands. Existing suppression/deduplication remains. |
| Privacy | Existing filtered microphone/camera/screen-capture OSD transitions; activity badges use current filtered PipeWire captures. |
| Device | Existing Wi-Fi, Bluetooth and power-profile OSD feedback. |
| Brightness | A changed controllable-display brightness percentage, or its feedback command. |
| Media track | The active MPRIS player's titled track changes while Playing, after 400 ms metadata settling. |
| Media Play / Resume | The active player's known non-Playing state changes to Playing. Waits for a title if needed. Pause, repeated Playing updates and first discovery do not announce an event. |
| Notifications | Eligible arrivals after existing filters/DND checks. Updates/closures update or remove the matching compact event; history is not replayed. The normal toast is suppressed only when the island handles the arrival. |
| Calls | Explicit notification category `call.incoming`/`call.ongoing`, KDE Connect `callReceived`, or conservative known-app incoming-call phrases. The source must supply updates/actions. |
| Countdown | Starting the shared session timer; its countdown updates each second. Completion becomes a persistent compact alert until acknowledged. |
| Alarm | Reaching an explicitly armed one-shot local-time deadline. Remains as a compact alert until dismissed or snoozed. |

Feedback is routed to the focused output's visible island. Timer/alarm ownership stays with the initiating output. Priority remains alarm/finished timer, calls, notifications, volume/brightness, media, countdown, clock. Ordinary notifications use an eight-entry FIFO with replacement by notification ID. Their display dwell and native expiry are paused while queued behind higher-priority events or held for interaction. The next notice receives its own display time; overflow falls back to the ordinary toast. Only the owning island consumes updates. Other transient categories coalesce repeated feedback and use the newest equal-priority event. Transient events use the configured dwell time; active tools are not replaced underneath the user by a different native panel.

#### Settings and activities

All event toggles, clock format, hover activation and dwell time are in **Bar → Effects**, including monitor overrides. Example:

```toml
[bar.default]
surface_mode = "dynamic"
screen_wrap = true
dynamic_media = true
dynamic_volume = true
dynamic_brightness = true
dynamic_notifications = true
dynamic_calls = true
dynamic_timers = true
dynamic_alarms = true
dynamic_hover_expand = true
dynamic_dwell_ms = 3500
dynamic_clock_format = "%H:%M"
dynamic_timer_seconds = 300
dynamic_alarm_time = "08:00"
dynamic_snooze_seconds = 300
```

The separate custom Clock & timers page has been removed with the duplicate expanded views. The shared session controller and its existing commands remain available for configured widget actions/keybinds:

```sh
noctalia msg island-activity timer-start 300
noctalia msg island-activity timer-cancel
noctalia msg island-activity alarm-arm 08:00
noctalia msg island-activity alarm-snooze
noctalia msg island-activity alarm-dismiss
```

Running/finished timers have a compact stop control. Ringing alarms have compact snooze and close controls. Calls use a **green phone** for a supplied accept/answer action, a **red phone** for a supplied decline/reject/hang-up action, and an X for dismissal; there is no duplicate Dismiss button or unsupported fake call control.

Timers/alarms survive bar/config rebuilds, not shell restarts. They do not wake the machine; wall-clock deadlines are checked after resume. Completion has one notification sound following shell audio preferences, and falls back to a normal persistent notification if its island is unavailable. There is not an existing native timer/alarm tool in this checkout: no replacement expanded timer panel is presented as one.

Call integration remains notification-backed. It cannot infer real ongoing state, answer/hang-up support or reliable termination without source-provided metadata/actions. Non-English known-app notices need explicit metadata for reliable classification. Native tools can take keyboard focus when opened.

`noctalia msg bar-island-toggle [bar-name] [monitor-selector]` opens/closes the corresponding native tool. Manual hide/show remains supported; automatic/smart hiding is not applied to Dynamic Island. The bar's thickness remains reserved if requested, with native tool content overlaying windows. The island uses a narrow edge strip; the normal native host owns the tool surface. This does not require a full-screen transparent island buffer.

### Screen wrap

Screen Wrap is shared **per output**, rather than allocating a frame for every bar. Participating bars retain widgets, ordering, layouts and materials and contribute tracks/island spans to one contour. A single fill/outline joins adjacent top/left and other tracks without doubled borders. Different bar materials blend at their junction; the first configured wrapped bar supplies the common thin-rail material. Frame width/rounding use the largest participating request. Separate displays have separate owners. The current GPU contour supports up to 32 bar tracks per output.

**Bar → Effects → Window Clearance** (`wrap_clearance`, 0–500 logical pixels, default **0**) adds space between the stable frame/bar footprint and application work area, including per-monitor overrides. **Reserve Space** enables the request. A transparent, non-interactive reservation surface handles each edge; requests combine by maximum, not addition. Positive clearance also reserves the thin rails on otherwise unused edges. Zero keeps the previous reservation behaviour. Visual surfaces ignore exclusive zones and stay at physical edges. Same-edge tracks and corner-safe widget insets derive from configured thickness, never animated extents. Existing saved margins remain available outside wrap mode; Opposite Edge Margin still contributes to the work-area request.

Requests that cannot fit an output are bounded to leave a nonempty work area and logged. Reservations are compositor requests, not window movement commands. Umbriel's scrolling columns, floating and fullscreen windows may extend past the usable area; Nythera cannot force their clipping or placement. Dynamic Island foreground surfaces now request only their visible thickness: the old left surface included unused contour padding. Curves remain in shared click-through frame buffers. There is no opaque mask or arbitrary monitor offset.


**Bar → Effects → Screen Wrap** connects the bar to a rounded frame around the display. It works with Full Bar, Floating Islands and Dynamic Island, on any bar edge, and can be overridden per monitor. **Frame Width** controls the thin rails (1–32 logical pixels, capped at half the bar thickness); **Frame Rounding** controls the desktop opening (0–100 logical pixels).

```toml
[bar.default]
screen_wrap = true
wrap_width = 6
wrap_radius = 20
```

Full Bar becomes the thick edge of the frame. Islands join the narrow rail on their chosen edge and keep their configured contents and size animations. The frame uses the bar's palette, background opacity, border and compositor-blur settings. It has no independently hardcoded colours or widgets. Use one wrapped bar per monitor.

While wrapped, the bar attaches to its selected edge, its drop shadow is suppressed, and its ends leave room for the frame. These are runtime adjustments: switching wrap off restores the saved margins, corners and shadow settings. The rails are click-through. With Window Clearance zero, only configured bar tracks reserve work area; positive clearance includes the other rails too. The frame remains visible while any participant is shown.

The renderer uses four disjoint edge buffers rather than a full-screen transparent buffer. Frame surfaces survive an individual participant being removed, and are released with the last participant or when output geometry changes. Placing independently configurable widgets on the other frame edges remains a separate design step.

Wrapped Islands share one continuous contour with the frame. Rounded junctions follow the bar's existing Corner Radius, including during island resizing, so the frame outline does not run through the islands. Widget ordering is unchanged; configured neighbouring tracks determine stable corner-safe content insets.

**Bar → Effects → Corner Join Distance** (`wrap_join_distance`, also available per monitor) controls whether the outer start/end islands merge into the adjacent screen corners. The default is **80 logical pixels**, twice the original 40px gap. Islands farther away retain the outer gap and curved rail junction; `0` disables corner merging. The centre island never merges into a screen corner. The same rule applies to the upper/lower ends of vertical bars.

Grouped Workspaces/Taskbar animates its own extent, group capsules and application
positions when workspace contents change. The containing island and following
widgets track that extent directly, using the same 300 ms cubic easing as Active
Window. Horizontal bars animate width; vertical bars animate height. Existing
global Motion enable/speed settings apply, with no additional toggle.


Shadow blur, offset, and alpha are global under `[shell.shadow]`. Bars only expose `shadow = true|false`.

`contact_shadow = true` adds a dark gradient at the seam between an attached panel and the bar, giving the panel a slight lifted-off-the-bar feel. It is independent of `shadow` and only takes effect on attached panels; the change applies on the next panel open.

`panel_overlap` controls how many logical pixels an attached panel is pulled into the bar so the two surfaces share an edge instead of leaving a hairline gap. The ideal value depends on your compositor and the output's fractional scale (it comes down to physical-pixel rounding), so it is tunable rather than fixed. The default is `1`. If you see a faint seam line, try `0`; if a gap appears, raise it. Negative values push the panel away from the bar. Because the right value tracks fractional scale, you can set it per monitor with a `[bar.<name>.monitor.*]` override on a mixed-scale multi-monitor setup. In the Settings GUI it lives under **Bar → Layout → Advanced**.

`capsule_thickness` sets the widget capsule size across the bar (its height on a horizontal bar, width on a vertical bar) as a fraction of the bar thickness. The default is `0.76`; `1.0` makes capsules fill the full bar thickness and lower values shrink them, leaving more margin on either side. It applies to every capsule on the bar regardless of per-widget content scale. In the Settings GUI it lives under **Bar → Capsules**.

`font_scale` multiplies widget text independently of icons, spacing, and other content. Its default is `1.0`, and its range is `0.2`–`2.5`. The effective text scale is the widget's normal content scale multiplied by the bar's `font_scale` and the widget's optional `font_scale`. It can also be set per monitor with a `[bar.<name>.monitor.*]` override; in Settings, select the monitor nested under the bar and use **Layout → Font Scale**.

`font_family` sets the typeface for this bar's widget labels. Leave it empty (the default) to inherit the global `[shell] font_family`. A single widget can override it with `[widget.<name>] font_family`, and it can be set per monitor with a `[bar.<name>.monitor.*]` override. The Settings GUI exposes a searchable font picker under **Bar → Widgets**, with a per-widget picker in each widget's settings.

`border_width` draws an inside outline using `border`. Attached panels stay borderless so they remain visually clean against the bar.

## Auto-hide

When `auto_hide = true`, the bar:

- Slides out once the pointer leaves the bar.
- With `auto_hide_delay_ms > 0`, waits that many milliseconds after the pointer leaves before sliding out. Moving the pointer back onto the bar cancels the wait. The default `0` hides immediately. The setting applies to pointer auto-hide, not Smart mode, explicit `bar-hide` commands, or the `show_on_workspace_switch` peek, which hides right after its brief reveal and cancels a pending wait. It can also be set per monitor.
- Slides back in when the pointer reaches the matching screen edge. With `margin_edge > 0`, the float gap is included in the layer surface so reveal works from the physical screen edge. With `margin_edge = 0`, the bar stays flush to the edge; pointer hit-testing still uses the full layer surface so reveal does not immediately cancel.
- While auto-hide is active, pointer hit-testing uses the full bar layer surface so entering from the edge strip does not immediately leave again.
- With `show_on_workspace_switch = true` (default), briefly reveals when the active workspace changes on that monitor, then hides again if the pointer is not over the bar.
- IPC `bar-show`, `bar-hide`, `bar-toggle`, and `bar-reserve-toggle` accept optional `[bar-name] [monitor-selector]` arguments; omit both to affect every bar instance. These commands change only the running shell and do not write configuration. `bar-show`/`hide`/`toggle` use the same hide/reveal animation instead of tearing down surfaces. With `auto_hide`, they retract or reveal the bar like pointer auto-hide; edge reveal still works after `bar-hide`. With `auto_hide` off, `bar-hide` hides the bar and always frees the compositor gap until `bar-show` (or `bar-toggle` while showing), regardless of `reserve_space`. `bar-reserve-toggle` temporarily toggles the exclusive zone reservation for the matched instances; panels opened from those bars use the temporary value.

`reserve_space` controls whether the bar keeps a compositor exclusive zone. With `auto_hide = false`, `reserve_space = true` keeps windows pushed away; `reserve_space = false` overlays the bar on top of full-screen clients. With `auto_hide = true`, `reserve_space = false` retracts the bar as an overlay (no gap); `reserve_space = true` keeps the gap while the bar slides out of view.

### Smart auto-hide

Set auto-hide to **Smart** in bar settings (or `smart_auto_hide = true` with `auto_hide = false` in config). The bar stays visible while the active workspace on that monitor is empty and hides when the workspace has windows. Window presence is detected from per-workspace window assignments when the compositor provides them, otherwise from the workspace `occupied` flag.

Windows reported as minimised by Umbriel, KDE Plasma, or labwc do not hide the bar. Minimising the last visible window keeps the bar visible; workspace occupancy and window counts still include minimised windows.

On labwc, workspace occupancy is inferred from focus because the compositor does not report each window's workspace (see the [workspaces widget](widgets/workspaces)).

- Mutually exclusive with pointer auto-hide (`auto_hide = true`); if both are set in config, smart auto-hide takes precedence.
- Uses the same slide animation and edge reveal strip while hidden.
- On compositors that report overview state (Niri, Umbriel), the bar is kept visible while overview is open.
- Re-evaluates on workspace changes, window open/close, and overview toggles.

`margin_opposite_edge` adds extra reserved space on the inward side of the bar (below a top bar, above a bottom bar, and so on for vertical bars). The bar itself does not move; the compositor exclusive zone grows so tiled and maximized windows stop further away. Use it when a compositor ignores or under-reserves struts - for example Labwc with a maximized window that still touches the bar. Requires `reserve_space = true`. The default is `0`.

`layer = "overlay"` shows the bar above fullscreen apps. Attached panels (for example Control Center when it attaches to the bar) follow the bar's layer. Floating panels keep their own layer (typically overlay), including when their screen position is `center`.

The IPC `bar-layer-set <top|overlay> [bar-name] [monitor-selector]` switches the layer of matching bar instance(s) at runtime; omit `bar-name` to update every bar. The change is transient and resets to the configured `layer` on the next config reload. This is handy for peeking the bar above a fullscreen window on a keybind, for example in niri:

```kdl
binds {
    Mod+B { spawn-sh "noctalia msg bar-layer-set overlay"; }
    Mod+Shift+B { spawn-sh "noctalia msg bar-layer-set top"; }
}
```

## Widget Capsule

Each widget can have a capsule (pill-shaped background + optional border). Settings cascade from bar defaults down to per-widget overrides.

### Bar-level defaults

Set under `[bar.<name>]` or `[bar.<name>.monitor.*]`:

| Setting                | Type   | Default             | Description                                                                                                                                                                                                                                                                   |
| ---------------------- | ------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `capsule`              | bool   | `false`             | `true` gives every widget a capsule unless `[widget.*]` sets `capsule = false`.                                                                                                                                                                                               |
| `color`                | string | *(unset)*           | Default icon + label color role for every widget on this bar; fixed hex colors are also supported.                                                                                                                                                                            |
| `icon_color`           | string | *(unset)*           | Overrides `color` for icons only on this bar; fixed hex colors are also supported. When unset, icons inherit `color`.                                                                                                                                                         |
| `capsule_radius`       | number | *(auto pill)*       | Default capsule corner radius in logical pixels before `scale` is applied (clamped 0–80). Also used by workspace pills and taskbar workspace groups. Omit to use automatic pill radius.                                                                                       |
| `capsule_fill`         | string | `surface_container` | Default capsule background color role; fixed hex colors are also supported.                                                                                                                                                                                                   |
| `capsule_foreground`   | string | *(unset)*           | Default icon + label color role for capped widgets; fixed hex colors are also supported.                                                                                                                                                                                      |
| `capsule_padding`      | number | `6`                 | Inner padding in logical pixels before `scale` is applied (clamped 0–48).                                                                                                                                                                                                     |
| `capsule_opacity`      | number | `1.0`               | Capsule background opacity (0.0–1.0).                                                                                                                                                                                                                                         |
| `capsule_border`       | string | *(omitted)*         | Color role for the capsule border; fixed hex colors are also supported. If omitted, no border by default. If present as `""`, no border.                                                                                                                                      |
| `capsule_border_width` | number | `1`                 | Capsule outline thickness in logical pixels before `scale` is applied (clamped 0–8). Only drawn when `capsule_border` resolves to a color.                                                                                                                                    |
| `hover_highlight`      | bool   | `true`              | Softly tint the widget under the mouse pointer with its own foreground color. Works with and without capsules; inside a capsule group only the hovered member lights up. The highlight never changes widget layout or spacing. Set `false` to disable the effect on this bar. |
| `show_tooltip`         | bool   | `true`              | Show hover tooltips for widgets on this bar. Set `false` to turn tooltips off for every widget on this bar without disabling clicks or scrolls; a widget's own `show_tooltip` overrides it.                                                                                   |

### Per-widget overrides

Set under `[widget.<name>]`:

| Setting                | Type    | Default                   | Description                                                                                                                                                                                                                                                                                                                                              |
| ---------------------- | ------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scale`                | number  | `1.0`                     | Multiplies the owning bar's `scale` for this widget only (clamped 0.2–2.5).                                                                                                                                                                                                                                                                              |
| `font_scale`           | number  | `1.0`                     | Additional text-only multiplier for this widget, combined with the owning bar's `font_scale` (clamped 0.2–2.5).                                                                                                                                                                                                                                          |
| `anchor`               | bool    | `false`                   | Pin this widget as the center lane's alignment anchor.                                                                                                                                                                                                                                                                                                   |
| `font_family`          | string  | *(from bar)*              | Typeface for this widget. Leave empty to inherit the owning bar's font.                                                                                                                                                                                                                                                                                  |
| `font_weight`          | integer | *(from bar)*              | CSS font weight `100`–`1000`. Leave unset to inherit the owning bar's weight.                                                                                                                                                                                                                                                                            |
| `capsule`              | bool    | *(from bar)*              | Omit to inherit bar flag; `false` disables; `true` forces on.                                                                                                                                                                                                                                                                                            |
| `capsule_radius`       | number  | *(from bar)*              | Per-widget corner radius (0–80). Omit or set `"auto"` to inherit the bar's `capsule_radius`; when the bar leaves it unset too, the automatic pill radius applies. `"auto"` is only accepted here: the bar's own `capsule_radius` takes a number or is omitted.                                                                                           |
| `capsule_fill`         | string  | *(from bar)*              | Capsule background color role; fixed hex colors are also supported.                                                                                                                                                                                                                                                                                      |
| `capsule_foreground`   | string  | *(from bar)*              | Icon + label color role when capsule is visible; fixed hex colors are also supported. `color` takes priority over this.                                                                                                                                                                                                                                  |
| `capsule_padding`      | number  | *(from bar)*              | Per-widget inner padding (0–48).                                                                                                                                                                                                                                                                                                                         |
| `capsule_opacity`      | number  | *(from bar)*              | Per-widget capsule background opacity.                                                                                                                                                                                                                                                                                                                   |
| `capsule_border`       | string  | *(from bar)*              | Color role for the capsule border; fixed hex colors are also supported. Omit to inherit bar policy. Present but empty/whitespace-only = no border.                                                                                                                                                                                                       |
| `capsule_border_width` | number  | *(from bar)*              | Per-widget capsule outline thickness (0–8). Omit to inherit the bar value.                                                                                                                                                                                                                                                                               |
| `color`                | string  | *(unset)*                 | Icon + label color role with or without capsule; fixed hex colors are also supported. Resolution order: `color` → `capsule_foreground` → built-in defaults.                                                                                                                                                                                              |
| `icon_color`           | string  | *(unset)*                 | Overrides `color` for icons only. Resolution order for icons: `icon_color` → `color` → `capsule_foreground` → built-in defaults. Labels always use `color`.                                                                                                                                                                                              |
| `interactive`          | bool    | `true` (spacers: `false`) | Set `false` to make the widget passive: hover highlight and tooltips are disabled, pointer events (clicks, scrolls) pass through to the bar underneath, and the **Actions** settings section is hidden. The widget is still drawn; use `enabled = false` to hide it entirely. Spacers default to non-interactive so they stay click-through layout gaps. |
| `show_tooltip`         | bool    | *(from bar)*              | Show this widget's hover tooltips. Set `false` to hide them while keeping the widget interactive. Omit to inherit the owning bar's `show_tooltip`. Has no effect when `interactive = false`, which already disables tooltips.                                                                                                                            |
| `scroll_repeat`        | string  | `auto`                    | Scroll action repetition: `auto` uses once-per-gesture for cycle commands and every-step for ramp commands; `gesture` always runs once per gesture; `steps` always runs for every quantized step.                                                                                                                                                        |
| `enabled`              | bool    | `true`                    | Show or hide this widget on the bar. Disabled widgets are not created and consume no resources.                                                                                                                                                                                                                                                          |

Prefer color role names so widget styling follows the active palette. Role names use **snake_case** (e.g. `on_surface`, `surface_container`, `secondary`). Use fixed hex colors only when you deliberately want a non-palette color; hex may use `#RGB`, `#RGBA`, `#RRGGBB`, or `#RRGGBBAA`. Invalid role names or malformed hex colors are treated as config errors.

The capsule is hidden automatically when a widget reports no visible ink (empty tray, absent battery, invisible root). Subclasses may override `Widget::shouldShowBarCapsule()`. The workspaces widget reuses its resolved `capsule_radius` for workspace pills. The taskbar also reuses its resolved `capsule_radius` for workspace group capsules when `group_by_workspace = true`, even if the taskbar's outer widget capsule is disabled.

```toml
[bar.default]
capsule         = true
capsule_fill    = "surface_container"
capsule_opacity = 0.9
capsule_border  = "outline_variant"

# Accent bar: primary fill + matching text
[bar.accent]
capsule            = true
capsule_fill       = "primary"
capsule_foreground = "on_primary"
capsule_padding    = 10
capsule_radius     = 8.0

[widget.volume]
capsule_fill   = "secondary"
capsule_radius = 0.0         # square this widget's capsule
capsule_border = ""          # no border on this widget

[widget.spacer]
type    = "spacer"
capsule = false
```

## Capsule groups

A **capsule group** is a container that holds several widgets and renders them inside one shared capsule with a single common style. A group is a real item in the lane - its members live *inside* it, so inserting another widget elsewhere can never split it. Grouping is managed entirely from the Settings GUI:

1. Open **Settings → Bar → Bar Widgets**.
2. **Drag one widget onto the middle of another** (using its drag handle) to instantly create a group from the two. Or tick the checkbox on two or more widgets in the same lane and click **Group** - they need not sit next to each other; the group takes the place of the first one. Either way they move into one group container and a style editor opens.
3. Edit the group's background, border, foreground, padding, spacing, radius, and opacity - every member updates together. Turning on **Accordion** collapses the group to its first widget until you hover it; **Reveal direction** picks which side the remaining widgets unfold on. Expanding an accordion keeps neighboring widgets anchored on the end side of the lane steady, including on vertical bars.
4. **Drag a widget onto the group** to add it; **drag a member out**, or use its eject button, to remove it. Reorder members by dragging them within the group. Drag the group's own handle to move the whole group along the lane or into another lane.
5. To dissolve a group, open its style editor and click **Ungroup** (its members return to the lane in place).

When dragging a widget, hovering the **middle** of another widget combines them into a group, while hovering the **top/bottom edge** drops it between widgets as a normal reorder.

Under the hood each group is one `[[bar.<name>.capsule_group]]` table holding an ordered `members` list plus the shared style, and the lane references the group with a single `group:<id>` token. You normally do not write these by hand:

```toml
[bar.default]
end = ["clock", "group:g1", "session"]   # the group occupies one lane slot

[[bar.default.capsule_group]]
id      = "g1"
members = ["network", "bluetooth", "volume"]
fill    = "surface_container"
padding = 6.0
opacity = 0.9
enabled = true
accordion = true                         # optional: collapse to the first widget, reveal on hover
accordion_direction = "end"              # "end" (default) or "start"
widget_spacing = 10                      # optional: gap between this group's widgets
# border, foreground, radius, enabled are optional
```

| Setting               | Type    | Default                    | Description                                                                                                                                   |
| --------------------- | ------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                  | string  | *(required)*               | Group identifier. Lane entries reference the group with `group:<id>`.                                                                         |
| `members`             | list    | *(required)*               | Ordered list of widget names belonging to this group.                                                                                         |
| `enabled`             | bool    | `true`                     | Show or hide the entire group on the bar. Disabled groups are not populated and their widgets consume no resources.                           |
| `fill`                | string  | `surface_container`        | Background color role for the shared capsule; fixed hex colors are also supported.                                                            |
| `border`              | string  | *(omitted)*                | Color role for the capsule border; fixed hex colors are also supported. Omit for no outline; present but empty (`""`) also means no outline.  |
| `border_width`        | number  | `1`                        | Capsule outline thickness in logical pixels (clamped 0–8). Only drawn when `border` resolves to a color.                                      |
| `foreground`          | string  | *(unset)*                  | Icon + label color role for all widgets inside this group; fixed hex colors are also supported.                                               |
| `padding`             | number  | `6`                        | Inner padding between the capsule edge and its widgets, in logical pixels (clamped 0–48).                                                     |
| `radius`              | number  | *(auto pill)*              | Capsule corner radius in logical pixels (0–80). Omit for automatic pill radius.                                                               |
| `opacity`             | number  | `1.0`                      | Capsule background opacity (0.0–1.0).                                                                                                         |
| `accordion`           | bool    | `false`                    | Collapse the group to its first widget; hovering the capsule expands it in place to reveal the rest. Needs at least two widgets in the group. |
| `accordion_direction` | string  | `end`                      | Where the hidden widgets unfold relative to the first one along the lane: `end` (after it) or `start` (before it).                            |
| `accordion_duration`  | integer | `200`                      | Duration of the unfold and collapse animations in milliseconds (0–2000, 0 is instant).                                                        |
| `accordion_delay_ms`  | integer | `0`                        | Milliseconds to hover before unfolding starts (0–2000, 0 reacts at once; collapse begins without this delay).                                 |
| `widget_spacing`      | integer | *(bar's `widget_spacing`)* | Gap between the group's widgets, in logical pixels. Omit to inherit the bar's `widget_spacing`.                                               |

A group's style can be overridden per monitor by declaring `[[bar.<name>.monitor.<match>.capsule_group]]` tables with matching `id` values. A reused widget name (e.g. several `spacer` instances) can appear in different groups independently - membership is positional, not a per-widget flag.
