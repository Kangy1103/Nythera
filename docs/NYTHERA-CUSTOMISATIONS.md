This document records **behavioural contracts**, not a frozen list of code to keep forever. During upstream integrations, preserve Nythera's intended behaviour while replacing obsolete implementations when needed. Use [REBRAND.md](../REBRAND.md) for identity, external APIs and migration contracts; [ARCHITECTURE.md](../ARCHITECTURE.md) for architectural invariants; and [SCOPE.md](../SCOPE.md) to distinguish committed scope from future ideas.

## Shared nebula background

**Implemented; runtime validation tracked in [the background guide](nebula-background-poc.md).** Preserve the accepted dark crimson appearance, slow movement, independent native-surface switches and background-only transparency. The dedicated Haze section uses existing `shell.panel.haze_*` persistence. Bars/islands stay clear, including in joined contours. Owners: `src/render/animation/surface_haze.*`, `src/render/programs/nebula_glsl.h`, native Surface lifecycle and tagged Box/Flex/screen-frame materials. Upstream surface, contour, frame-callback or settings refactors must preserve these contracts. Comprehensive performance benchmarking remains issue #18 work.

## Discord / Vesktop template

The opt-in **Discord / Vesktop** built-in template ships Nythera's System24 stylesheet with pinned System24/Midnight dependencies, MIT notices and embedded artwork. It follows the application palette, leaves client theme selection manual, and removes only its generated `nythera.theme.css` when disabled. Owners: `assets/templates/discord/`, `assets/templates/builtin.toml`, `tools/build-discord-template.py`. Default configuration selects no built-in templates. Implementation uses the existing template engine; live client reload and visual acceptance require checking after CSS or upstream selector changes. See `docs/user/templates/official/discord.mdx` for setup and maintenance.

## Updating the register

- When a Nythera feature is added, substantially redesigned or retired, update its entry (or add one) in the same change.
- Record the **visible/user contract**, owning files or symbols confirmed from source, and upstream dependencies. Prefer stable paths/subsystems over brittle line numbers.
- Label entries **verified implemented**, **experimental**, **planned** or **unverified** as appropriate. Do not promote an item solely because it appears in a README.
- Upstream integration reports should identify entries affected, how their behaviour was verified, and any explicit deferrals.
- This file does **not** override user decisions, `ARCHITECTURE.md`, `REBRAND.md`, or the need to inspect live code. It is a navigation aid for agents.
